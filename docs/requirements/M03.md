# M03 — Product information and master data

- **Priority:** P0/P1 · **Release:** R2 · **Stage:** 7 · **Roadmap:** §5 M03, §16 D01, §29 (Product domain), §31
- **Purpose:** The single trusted product truth (P-02) every channel shares — items, barcodes, units, tax, MRP and safety information. A wrong product record multiplies into every sale, order and report, so duplicate control and clean units are foundational.

> Appendix B records; store-fact gaps marked `⟳ AVR-##`; §5 cross-cutting standard inherited. Related extension: **D01** (GS1/GTIN barcodes, weight-price barcodes, pack hierarchy, allergens, recall block, app content/typo tolerance).

## M03-FR-01 — Hierarchy, brand, variants and attributes
- **Shall:** provide a department/category hierarchy with brand, manufacturer, variants and configurable attributes, so every product sits in exactly one place and can be found and reported on.
- **Actors/scope:** Product/Merchandising user (maintain), Owner/Manager (approve new category). **Preconditions:** org hierarchy (M01).
- **Flow:** create hierarchy → add brand/manufacturer → create product with attributes/variants → approve → publish. **Alt/error:** incomplete product saved as draft; category with active products cannot be deleted.
- **Rules:** one primary category per product; variants share a parent; attributes are typed and validated (§29.1).
- **Permissions (§28):** Product user maintains; structural category change approved. **Offline (§31):** full read from signed versioned local cache; edits are cloud-approved and published.
- **Audit/privacy:** all changes immutable (M34-FR-01); no personal data. **Integration/reporting:** API-02; catalogue completeness report.
- **Acceptance:** a product cannot be saved without a category and tax class; a report by category returns the correct set; a category with stock cannot be deleted.

## M03-FR-02 — Barcodes, UOM, case-pack and variable weight
- **Shall:** support multiple barcodes per item (GS1/GTIN/EAN/UPC + internal), UOM and case-pack conversion, variable-weight/embedded-price barcodes, and bundles.
- **Actors/scope:** Product user; consumed by POS (M12), receiving (M07), inventory (M08). **Preconditions:** product exists (FR-01).
- **Flow:** add barcodes → define base UOM + pack hierarchy (unit-inner-case-pallet) + conversions → configure variable-weight barcode parsing → define bundles. **Alt/error:** duplicate barcode across items blocked; ambiguous weight-barcode pattern rejected.
- **Rules:** a barcode maps to exactly one sellable item; conversions are exact and reversible; **quantity precision is UOM-aware** (§29.1); weight barcodes parse to item + weight/price deterministically.
- **Permissions (§28):** Product user. **Offline (§31):** full from local cache — POS must scan and price these with the network cable out.
- **Audit/privacy:** barcode/UOM changes audited. **Integration/reporting:** API-02; a barcode-coverage/duplicate report.
- **Acceptance:** the same barcode cannot belong to two items; a case scanned at receiving converts to the correct unit count; a variable-weight barcode rings up the correct weight and price **offline**.

## M03-FR-03 — Tax, MRP, ingredients, allergens, origin and storage
- **Shall:** hold HSN/tax class, MRP, and safety/compliance content — ingredients, allergens, nutrition, country of origin and storage conditions — with regulated-item and recall-block flags (D01-FR-05).
- **Actors/scope:** Product user + Finance (tax) + food-safety validator. **Preconditions:** product exists.
- **Flow:** assign HSN/tax + MRP → enter safety content → set regulated/recall flags → approve. **Alt/error:** a food item without required allergen data cannot be published `⟳ AVR-11/AVR-12`; recall-blocked item cannot be sold or ordered.
- **Rules:** MRP and tax are effective-dated and validated; Legal Metrology label fields present for packed/weighed goods (§9.3); a recall block stops POS sale and purchase.
- **Permissions (§28):** tax change with Finance approval. **Offline (§31):** tax/MRP full from local cache; recall block honoured offline.
- **Audit/privacy:** tax/MRP/recall changes audited; compliance evidence retained (M34-FR-03). **Integration/reporting:** API-02; tax-mapping and allergen-completeness reports.
- **Acceptance:** an item flagged recall-blocked cannot be added to a bill even offline; MRP change is effective-dated and historised; a food item missing allergen data is blocked from publish.

## M03-FR-04 — Lifecycle, assortment, substitutes, images, duplicates and bulk
- **Shall:** manage product lifecycle (new/active/discontinued/clearance), assortment, substitutes, images, **duplicate detection**, and bulk maintenance.
- **Actors/scope:** Product/Merchandising user. **Preconditions:** products exist; import service (M30) for bulk.
- **Flow:** set lifecycle state → assign assortment/substitutes → add images/app content (D01-FR-06) → run duplicate detection → bulk-edit via validated import. **Alt/error:** suspected duplicates queued for review, never auto-merged; bulk job with row errors previews before commit (M30).
- **Rules:** duplicate detection on barcode/name/attributes; merges are approved and reversible via compensating record; lifecycle drives sellability.
- **Permissions (§28):** bulk maintenance is maker-checker. **Offline (§31):** lifecycle/assortment read from cache; bulk edits are online/approved.
- **Audit/privacy:** merges and bulk changes audited with before/after. **Integration/reporting:** API-02/API-11; duplicate and data-quality-score reports (M30-FR-04).
- **Acceptance:** two records for the same barcode are flagged as duplicates and require approval to merge; a discontinued item stops being sellable; a bulk price/attribute import previews row errors before any change commits.

## Module acceptance & test families
- Unit: barcode uniqueness, UOM/pack conversion, weight-barcode parsing, duplicate detection, tax/MRP effective dating.
- Offline (§31/QG-04): scan + variable-weight pricing + recall block with the network cable out.
- Data quality (M30): bulk import validate-preview-approve-commit with row-level errors.
- Audit (NFR-15): every product/tax/MRP change reconstructable from evidence.
