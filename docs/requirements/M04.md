# M04 — Merchandising, space and planograms

- **Priority:** P2 · **Release:** R2 (foundation) / later polish · **Stage:** 7 · **Roadmap:** §5 M04, §16 D02, §31
- **Purpose:** Decide what each store carries and where it sits on the shelf, so the right range is stocked, shelves are replenished to plan, and space earns its keep (sales per square foot). Related extension: **D02** (open-to-buy, seasonal assortment, store clustering, range gaps, private label, supplier-funded display space).

## M04-FR-01 — Store assortment and range review
- **Shall:** define per-store assortment and support periodic range review (add/keep/drop) with reasons.
- **Actors/scope:** Merchandising/Department Manager; Owner approves major range change. **Preconditions:** products (M03), store (M01).
- **Flow:** build assortment from catalogue → review performance/gaps → propose add/drop → approve → publish to store. **Alt/error:** dropping an item with stock triggers a clearance/markdown path (M05/M10), not silent removal.
- **Rules:** an item sold in a store must be in its assortment; range changes are effective-dated; drop decisions record a reason (D02 range gaps).
- **Permissions (§28):** Department Manager within scope; Owner for major change. **Offline (§31):** assortment read from local cache.
- **Audit/privacy:** assortment changes audited. **Integration/reporting:** API-02; range-gap and assortment-coverage reports.
- **Acceptance:** an item not in a store's assortment does not appear in that store's ordering/replenishment; a dropped item with stock is routed to clearance, not deleted.

## M04-FR-02 — Aisle, rack, bay, shelf and capacity mapping
- **Shall:** model the physical shelf layout (aisle/rack/bay/shelf) with capacity per location, so pick paths and replenishment know where things are.
- **Actors/scope:** Merchandising; consumed by picking (M19) and replenishment (M09). **Preconditions:** store (M01).
- **Flow:** define locations → assign products to shelf locations with capacity → maintain. **Alt/error:** a product mapped to two conflicting primary shelf locations is flagged.
- **Rules:** each product has a primary shelf location per store; capacity drives replenishment quantity; **shelf location sequences the picker's route** (feeds M19 — the profitability lever the audit highlights).
- **Permissions (§28):** Merchandising. **Offline (§31):** layout read from cache for handheld/picker.
- **Audit/privacy:** layout changes audited. **Integration/reporting:** API-02/API-04; planogram-compliance and space reports.
- **Acceptance:** a picker's list orders items by shelf location so the store is walked once; capacity feeds a replenishment task when shelf stock is low.

## M04-FR-03 — Planogram creation, compliance and replenishment tasks
- **Shall:** create planograms, check compliance, and generate shelf-replenishment tasks.
- **Actors/scope:** Merchandising (create), Store staff (execute tasks). **Preconditions:** shelf mapping (FR-02).
- **Flow:** build planogram → publish → detect gaps/non-compliance → raise replenishment task (WF-06) → confirm. **Alt/error:** compliance exceptions surface for action, not silence (P-08).
- **Rules:** replenishment tasks derive from planogram + capacity + availability (M08); tasks route to the responsible role (M25).
- **Permissions (§28):** Merchandising creates; staff execute within scope. **Offline (§31):** tasks cached to handheld; completion queued and synced.
- **Audit/privacy:** planogram versions and task completion audited. **Integration/reporting:** API-02; compliance and out-of-shelf reports.
- **Acceptance:** a shelf gap generates a replenishment task to the right person; a planogram change is versioned; compliance is measurable.

## M04-FR-04 — Display-space contracts, heat-map readiness, sales per sq ft
- **Shall:** record supplier-funded display-space contracts, be heat-map ready, and report sales per square foot.
- **Actors/scope:** Merchandising + Finance (funding). **Preconditions:** planogram + sales data (M12).
- **Flow:** record display contract + funding → link to space → measure performance → report sales/sq ft. **Alt/error:** expired display contract flags for renewal/removal.
- **Rules:** supplier display funding is tracked against the space it funds (D02-FR-06) and reconciled in finance (M23); sales/sq ft computed from mapped space + sales.
- **Permissions (§28):** Finance approves funding terms. **Offline (§31):** reporting online (last-synced).
- **Audit/privacy:** contract and funding changes audited. **Integration/reporting:** API-10; sales-per-sq-ft and display-effectiveness reports.
- **Acceptance:** a display-space contract with funding is recorded and reconciles to finance; sales/sq ft is reported by area; an expired display contract raises an alert.
