# M11 — Fresh food and internal production

- **Priority:** P2 · **Release:** R2 (foundation) / R6 (full fresh ops) · **Stage:** 8 / 16 · **Roadmap:** §5 M11, §9.3, §31
- **Purpose:** Run in-store production (bakery, kitchen, deli, meat/fish) — recipes, raw-material issue, yield and loss, weighed packing with scale labels, and quality release. **Conditional:** build only for departments the store actually operates (§2.2, `⟳ AVR-12`).

> **Do not build a module for a department you do not have** (roadmap §2.2 / Annexure H Stage 16). Confirm applicable departments in Stage 1 (AVR-12) before building beyond the foundation.

## M11-FR-01 — Recipes/BOM, raw-material issue, production plan, batch output
- **Shall:** define recipes/BOM, issue raw materials, plan production and record batch output.
- **Actors/scope:** Production staff/Department Manager. **Preconditions:** products & ingredients (M03), stock (M08).
- **Flow:** define recipe/BOM → plan production → issue raw materials (stock event out) → record finished batch (stock event in) with its own batch/expiry. **Alt/error:** issuing more than available blocked; output without required inputs flagged.
- **Rules:** production consumes inputs and creates outputs as **ledger events** (M08); finished goods get batch + expiry (M10); cost rolls up from inputs (FR-02).
- **Permissions (§28):** production posting by authorized staff. **Offline (§31):** production capture queue-capable; reconciled on sync.
- **Audit/privacy:** issue/output audited via ledger. **Integration/reporting:** API-04; production and yield reports.
- **Acceptance:** producing a batch consumes the recipe inputs and creates a finished batch with expiry; you cannot issue more raw material than on hand.

## M11-FR-02 — Catch/variable weight, yield, trimming/process loss, costing
- **Shall:** handle variable/catch weight, compute yield and trimming/process loss, and cost outputs accordingly.
- **Actors/scope:** Production staff/Finance. **Preconditions:** production (FR-01).
- **Flow:** capture input vs output weights → compute yield and loss → allocate cost to output (incl. loss). **Alt/error:** yield outside expected range flags for review.
- **Rules:** cost of output includes process loss; variable weight uses UOM-aware precision (§29.1); yield variance is an exception (P-08).
- **Permissions (§28):** costing reviewed by Finance. **Offline (§31):** weight capture offline; costing reconciles online.
- **Audit/privacy:** yield/cost audited. **Integration/reporting:** API-04/API-09; yield and production-cost reports.
- **Acceptance:** output cost reflects input cost plus process loss; an abnormal yield is flagged; variable weights compute correct cost/price.

## M11-FR-03 — Packing, scale labels, shelf life, quality release, repacking
- **Shall:** pack finished goods with scale labels (weight/price/expiry), assign shelf life, release on quality, and support repacking.
- **Actors/scope:** Production staff/QC. **Preconditions:** production output (FR-01), scale integration (D14).
- **Flow:** pack → print scale label (weight-price barcode, Legal Metrology fields) → set shelf life → quality release → available for sale (or repack). **Alt/error:** label missing mandatory metrology fields blocked; expired shelf-life not released.
- **Rules:** scale labels carry Legal-Metrology-compliant declarations (§9.3); weight-price barcode matches M03-FR-02 parsing; released stock enters availability (M08).
- **Permissions (§28):** quality release by authorized QC. **Offline (§31):** labelling/packing works at the counter offline.
- **Audit/privacy:** release and repack audited. **Integration/reporting:** API-04; packing and label-compliance reports.
- **Acceptance:** a scale label prints correct weight/price/expiry and scans correctly at POS; stock is sellable only after quality release; a repack is traceable to its source batch.

## M11-FR-04 — Bakery, central kitchen, deli, meat/fish configuration (where applicable)
- **Shall:** configure department-specific production (bakery, central kitchen, deli, meat/fish) for the departments the store operates.
- **Actors/scope:** Department Manager/Admin. **Preconditions:** department confirmed `⟳ AVR-12`.
- **Flow:** enable the applicable department → configure its recipes/processes/labels → operate. **Alt/error:** a department not operated is not built/enabled.
- **Rules:** conditional per §2.2; each enabled department meets its compliance (FSSAI, metrology, cold-chain per M10).
- **Permissions (§28):** department enablement is owner-approved config (M01-FR-03). **Offline (§31):** per the production flows above.
- **Audit/privacy:** configuration audited. **Integration/reporting:** API-04; per-department production reports.
- **Acceptance:** only confirmed departments are enabled; each enabled department's production, labelling and compliance work end-to-end.
