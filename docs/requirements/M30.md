# M30 — Import, export and data quality

- **Priority:** P0/P1 · **Release:** R2 · **Stage:** 7 · **Roadmap:** §5 M30, §16 D03-FR-02, §31, NFR-12 (portability)
- **Purpose:** Get data in and out safely, and keep it clean. **This module carries the store's #1 daily pain: bulk supplier-invoice import** (audit A-03) — make it work with a real 80+ line invoice first. Exports guarantee no lock-in (NFR-12, OD-09).

## M30-FR-01 — Template-driven import: validate → preview → approve → commit
- **Shall:** import any authorized domain via templates, with a validate → preview → approve → commit pipeline (nothing changes until approved).
- **Actors/scope:** authorized domain user + approver. **Preconditions:** templates defined; target module rules (e.g. M03, M07).
- **Flow:** upload file/template → validate rows → preview effect (incl. errors) → approve → commit. **Alt/error:** invalid rows shown per-row (FR-04); a rejected import commits nothing.
- **Rules:** commit is atomic per job with rollback (FR-04); validation applies the target module's business rules; **bulk supplier-invoice import (OCR/e-invoice, D03-FR-02)** feeds M07 three-way match — build and prove it first (A-03).
- **Permissions (§28):** import approved (maker-checker) for masters/financial data. **Offline (§31):** import is online/edge admin; POS unaffected.
- **Audit/privacy:** every import job audited with who/what/when. **Integration/reporting:** API-11/API-12; import job report.
- **Acceptance:** a **real 80+ line supplier invoice imports in one go and is correct**, timed against manual entry (audit A-03 owner check); an import with bad rows previews the errors and commits nothing until approved.

## M30-FR-02 — Exports for every authorized master and transaction domain
- **Shall:** export every authorized master and transaction domain in open, documented formats.
- **Actors/scope:** authorized users, Auditor, Owner. **Preconditions:** data classification (PRV).
- **Flow:** select domain + scope → export in open format (CSV/JSON) with schema. **Alt/error:** export of personal/payment data is access-controlled and logged (PRV).
- **Rules:** **no proprietary-only route to retrieve business data** (NFR-12, OD-09); exports honour role/branch scope and data classification.
- **Permissions (§28):** export scoped; sensitive exports restricted (§28 auditor limits). **Offline (§31):** online.
- **Audit/privacy:** exports logged (who/what); PII exports controlled. **Integration/reporting:** API-11.
- **Acceptance:** every authorized domain can be exported in an open format with its schema; a restricted user cannot export data outside their scope; exports are logged.

## M30-FR-03 — Duplicate, mandatory-field, reference and reconciliation controls
- **Shall:** enforce duplicate detection, mandatory fields, referential integrity and reconciliation controls on import.
- **Actors/scope:** import users. **Preconditions:** target rules (M03 etc.).
- **Flow:** on import, check duplicates/mandatory/reference/reconciliation → block/flag failures. **Alt/error:** duplicates queued for review, never auto-merged (M03-FR-04).
- **Rules:** referential integrity enforced (no orphan references); reconciliation totals must match for financial imports.
- **Permissions (§28):** override of a control is approved and audited. **Offline (§31):** online.
- **Audit/privacy:** control failures audited. **Integration/reporting:** API-12; data-quality-control report.
- **Acceptance:** a duplicate row is flagged not silently merged; a row missing a mandatory field is rejected with the reason; a financial import that doesn't reconcile is blocked.

## M30-FR-04 — Job history, row-level errors, rollback and data-quality score
- **Shall:** keep job history with row-level errors, support rollback, and compute a data-quality score.
- **Actors/scope:** import users, Data Steward, Owner. **Preconditions:** import jobs (FR-01).
- **Flow:** run job → record row-level results → roll back a committed job if needed → compute/publish data-quality score. **Alt/error:** rollback restores prior state via compensating records (append-only, §29.1).
- **Rules:** every job is auditable and reversible; data-quality score tracked over time (feeds Stage 1 baseline B-style measures).
- **Permissions (§28):** rollback approved. **Offline (§31):** online.
- **Audit/privacy:** job history immutable. **Integration/reporting:** API-12; job-history and data-quality-score reports.
- **Acceptance:** a committed import can be rolled back cleanly; row-level errors are visible per job; the data-quality score reflects real data health.
