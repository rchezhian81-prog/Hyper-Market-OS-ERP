# M33 — Platform administration and support

- **Priority:** P0 · **Release:** R1 · **Stage:** 5 · **Roadmap:** §5 M33, §16 D12, §35 (SEC-11), §31
- **Purpose:** Run the platform safely — settings, jobs, feature flags, device/version control, and **time-bound, audited support access with no perpetual back door** (SEC-11). Production requires at least two named administrators (§19.1 / M02).

## M33-FR-01 — Tenant/company settings, jobs, feature flags, configuration history
- **Shall:** manage company/tenant settings, background jobs, feature flags and full configuration history.
- **Actors/scope:** Platform Admin. **Preconditions:** org (M01), config service (M01-FR-03).
- **Flow:** manage settings/flags → schedule/monitor jobs → view versioned config history. **Alt/error:** a failed job alerts and is retryable; high-impact flag change is approved (M01-FR-03).
- **Rules:** all config versioned with rollback (M01-FR-03); jobs observable (M35); no routine business approvals by admins (§28).
- **Permissions (§28):** Platform Admin; **no business transactions** (§28). **Offline (§31):** settings publish to edge as signed packs.
- **Audit/privacy:** all admin changes audited. **Integration/reporting:** API-11; config-history and job reports.
- **Acceptance:** every setting/flag change is versioned and reversible; a failed job is visible and retryable; an admin cannot post a business transaction.

## M33-FR-02 — Device, terminal, application version, remote-session controls
- **Shall:** register and control devices/terminals, manage application versions, and control remote sessions.
- **Actors/scope:** Platform/Security Admin. **Preconditions:** devices (M01/§33 hardware).
- **Flow:** register device → assign to lane/branch → manage app version (incl. **minimum supported version / forced upgrade** for mobile, A-10) → control remote sessions. **Alt/error:** an unregistered/rooted device is blocked; a broken release can be remotely killed (A-10).
- **Rules:** **server supports current + previous app version; forced-upgrade with a minimum version; remote kill for a broken release** (roadmap mobile-safety, A-10); signed updates only (§35).
- **Permissions (§28):** device/version control by admin; audited. **Offline (§31):** edge devices cache registration; version policy enforced on reconnect.
- **Audit/privacy:** device/version/session actions audited. **Integration/reporting:** API-11; device-fleet and version reports.
- **Acceptance:** an out-of-date app below the minimum version is forced to upgrade; a broken release can be remotely disabled; only registered devices operate.

## M33-FR-03 — Controlled, audited support access with time-bound approval
- **Shall:** grant support/elevated access only with owner approval, time-bound, session-logged, and auto-expiring.
- **Actors/scope:** Support/Platform Admin; Owner approves. **Preconditions:** IAM (M02-FR-04 emergency access).
- **Flow:** request support access → owner approves with a time box → access granted + session recorded → auto-expire → review. **Alt/error:** access cannot be silently extended; expired access is revoked automatically.
- **Rules:** **no perpetual support access** (SEC-11); every support session is logged/recorded; least privilege for the specific task.
- **Permissions (§28):** owner approves; requester ≠ approver. **Offline (§31):** support access is online/governed.
- **Audit/privacy:** full session record retained (who/why/duration/actions). **Integration/reporting:** API-11; support-access report.
- **Acceptance:** support access expires automatically at its limit; every support session is recorded and attributable; access cannot be extended without a new approval.

## M33-FR-04 — Status centre, diagnostics, licence/entitlement, service management
- **Shall:** provide a status centre, diagnostics, licence/entitlement management and service management.
- **Actors/scope:** Platform Admin, Owner. **Preconditions:** observability (M35).
- **Flow:** view system status/health → run diagnostics → manage licences/entitlements → track service requests. **Alt/error:** an expiring licence/entitlement alerts a real person.
- **Rules:** status reflects real health (M35 signals); entitlements gate features (ties M36 readiness).
- **Permissions (§28):** admin scope. **Offline (§31):** edge health shown even when cloud link is down (§31 owner dashboard freshness).
- **Audit/privacy:** service actions audited. **Integration/reporting:** API-11; status and licence reports.
- **Acceptance:** the status centre shows real system health including offline/sync state; an expiring licence raises an alert to a named owner; diagnostics help resolve an incident.
